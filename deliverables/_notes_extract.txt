[Normal] Single-cell analysis of immune response to nanoplastic particles
[Normal] 1. Biological context
[Normal] Nanoplastics are very small plastic particles (often in the nanometer range). When they enter the blood, they can interact with immune cells in peripheral blood. This project studies whether particle size changes that response:
[Normal] All four samples come from one donor. Cells are PBMC (peripheral blood mononuclear cells): mainly T cells, B cells, NK cells, monocytes, and some dendritic cells.
[Normal] We use single-cell RNA sequencing (scRNA-seq). Instead of averaging RNA across millions of mixed cells (bulk RNA-seq), you measure RNA in each cell separately. That helps see:
[Normal] Which cell types respond to nanoplastics?
[Normal] Which genes change in each type?
[Normal] Are effects specific to 40 nm, 200 nm, or only seen in the mixture?
[Normal] The scientific question: How does nanoparticle size reshape the immune transcriptome at single-cell resolution?

[Normal] 3. How genes and cells are represented — and how they relate
[Normal] 3.1 The basic idea: a matrix
[Normal] scRNA-seq data is stored as a count matrix:
[Normal] Each row = one cell (one biological unit).
[Normal] Each column = one gene (one feature you measure).
[Normal] Each value = how many UMIs / reads were detected for that gene in that cell (expression strength). Approximate number of captured mRNA molecules from the gene were detected after sequencing and deduplication, reflecting how highly that gene is transcribed in that cell relative to other genes and other cells.
[Normal] So the relationship is: One cell has many genes measured; one gene is measured in many cells. In code (Scanpy / AnnData), this is usually stored as adata.X: cells × genes (rows = cells, columns = genes in AnnData convention).
[Normal] 3.2 What is a “cell” in the data?
[Normal] Each captured cell gets:
[Normal] Barcode — unique ID, e.g. AAACCCAAGACGCATG-1
[Normal] In adata.obs_names (row index of the matrix).
[Normal] Metadata (obs) — information about the cell, not expression:
[Normal] sample_id — which file / batch (Sample2, Sample4, …)
[Normal] condition — PSNP_40nm, PSNP_200nm, PSNP_mix_40_200, control
[Normal] cell_type_marker — T cell, B cell, monocyte, … (after annotation)
[Normal] cluster — Leiden cluster number
[Normal] QC: n_genes_by_counts, total_counts, pct_counts_mt
[Normal] Cell = identity (barcode) + metadata (labels) + expression profile (thousands of numbers)
[Normal] 3.3 What is a “gene” in the data?
[Normal] Each gene has:
[Normal] Gene symbol — e.g. CD3D, LYZ, ISG15
[Normal] In adata.var_names (column index).
[Normal] Optional gene metadata (var) — e.g. whether it’s highly variable (highly_variable), mitochondrial (mt).
[Normal] A gene is a column: its values across all cells form an expression vector. That is a list of expression values (UMI counts), one number per cell, showing how strongly that gene is detected across the entire dataset.
[Normal] For example, the gene LYZ might have values [2, 120, 3, …] across thousands of cells—high in monocytes, low in T cells. Differential expression analysis compares these vectors between conditions (e.g. control vs 40 nm exposure) to see whether a gene is up- or down-regulated.
[Normal] 3.4 Relationship between cells and genes (intuition)
[Normal] GENES (features)
[Normal] CD3D   LYZ   MS4A1  ...
[Normal] ┌─────────────────────────
[Normal] Cell 1    │  high  low   low      →  T cell profile
[Normal] (T cell)  │
[Normal] ├─────────────────────────
[Normal] Cell 2    │  low   high  low      →  Monocyte profile
[Normal] (mono) │
[Normal] ├─────────────────────────
[Normal] Cell 3    │  low   low   high     →  B cell profile
[Normal] (B cell)  │
[Normal] └─────────────────────────
[List Paragraph] Similar cells → similar rows
[Normal] Each row is one cell’s expression across all genes. Cells of the same type (e.g. two T cells) tend to have similar values in the same columns, so their rows look alike. That’s why they cluster together on a UMAP.
[List Paragraph] Marker genes → columns high only in certain cell types
[Normal] A marker gene is strongly expressed in one cell type and weak elsewhere. That column is high in rows of that type (e.g. LYZ high in monocytes) and low in others—used to label cell types.
[List Paragraph] DE analysis → compare gene columns within one cell type (control vs 40 nm)
[Normal] You first keep only one cell type (same rows). Then, for each gene (column), you test whether expression differs between control and 40 nm cells. That finds genes up- or down-regulated by treatment in that type, without mixing T cells, B cells, etc.
[Normal] 3.5 AnnData: how Python organizes this

[Normal] Relationship rule:

[Normal] adata.var has same number of rows as adata.X has columns.
[Normal] Row i of X = expression of all genes in cell i.

[Normal] In AnnData / Scanpy (used in this project), each ROW is one cell and each COLUMN is one gene. The value at (cell i, gene j) is how many UMIs (deduplicated reads) were detected for that gene in that cell.
[List Bullet] One cell → one row → thousands of expression values (one per gene)
[List Bullet] One gene → one column → expression measured in every cell

[Heading 2] 2.2 What is a cell in the data?
[Normal] Each captured cell has three layers of information:
[List Bullet] Barcode — unique ID (e.g. AAACCCAAGACGCATG-1), stored as adata.obs_names
[List Bullet] Metadata (adata.obs) — sample_id, condition (40nm/200nm/mix/control), cell_type, cluster, QC metrics

[Heading 2] 2.3 What is a gene in the data?
[Normal] Each gene is a column. Gene symbols (CD3D, LYZ, ISG15, …) are in adata.var_names. Optional gene metadata is in adata.var (e.g. highly_variable, mitochondrial flag).

[Heading 2] 2.4 How cells and genes relate (intuition)
[Normal] Similar cells have similar rows (similar patterns across genes). Marker genes are columns that are high only in certain cell types. Differential expression compares columns (genes) between two groups of rows (cells) of the same type.

[Normal] adata.X — Main expression matrix (cells × genes), often normalized/log-transformed
[Normal] adata.layers["counts"] — Raw counts before normalization — kept for DE and pseudobulk

[Normal] adata.var — One row per gene: e.g. highly_variable, mt
[Normal] adata.obsm["X_umap"] — 2D coordinates per cell for plotting
[Normal] Rule: adata.obs has the same number of rows as adata.X. adata.var has the same number of rows as adata.X has columns. Row i of X is the expression of all genes in cell i.

[Heading 1] Part 3: Biological and Genomic Background
[Heading 2] 3.1 What is the biological question?
[Normal] Nanoplastics (tiny plastic particles, often < 1 µm) can enter the bloodstream and interact directly with immune cells. Particle size (e.g. 40 nm vs 200 nm) may change how strongly and in which cell types the immune system responds.
[Normal] This project uses single-cell RNA sequencing (scRNA-seq) on human peripheral blood immune cells (PBMC) from one donor exposed to:
[List Bullet] Sample 1: 40 nm carboxylated polystyrene nanoparticles (PSNPs)
[List Bullet] Sample 2: 200 nm PSNPs
[List Bullet] Sample 3: mixture of 40 nm + 200 nm
[List Bullet] Sample 4: control (no exposure)
[Heading 2] 3.2 What is scRNA-seq?
[Normal] Bulk RNA-seq measures average gene expression across millions of cells mixed together. scRNA-seq captures RNA from thousands of individual cells separately.
[Normal] Key concepts:
[List Bullet] Gene expression: how much each gene is transcribed into mRNA in a cell.
[List Bullet] UMI / counts matrix: table of cells (rows) × genes (columns) with read counts (AnnData convention).
[List Bullet] Cell barcode: unique ID for each captured cell (e.g. AAACCCAAGACGCATG-1).
[List Bullet] Feature: usually a gene; sometimes other features in the assay.
[Heading 2] 3.3 PBMC and immune cell types
[Normal] PBMC (peripheral blood mononuclear cells) include lymphocytes and monocytes. Major types in this project:
[Heading 2] 3.4 Core bioinformatics concepts used in this pipeline
[Normal] Quality control (QC): Remove damaged cells, empty droplets, and doublets before analysis. Metrics: number of genes detected, total UMI counts, % mitochondrial genes (MT-). High MT% often means dying/stressed cells.
[Normal] Normalization: Cells have different sequencing depth. normalize_total scales each cell to the same total counts; log1p stabilizes variance for downstream statistics.
[Normal] Highly variable genes (HVG): Genes that vary most across cells carry biological signal; ~3000 HVGs are used for dimensionality reduction instead of all ~20,000 genes.
[Normal] PCA (Principal Component Analysis): Linear reduction: thousands of genes → ~30 principal components capturing main variation.
[Normal] Batch correction / integration: Four samples were processed separately → technical 'batch' effects. Combat adjusts expression in PCA space so cells cluster by biology, not by sample file.
[Normal] UMAP: Non-linear 2D embedding for visualization. Similar cells appear close together.
[Normal] Leiden clustering: Groups cells into clusters (communities) on a nearest-neighbor graph.
[Normal] Cell type annotation: Assigning labels (T cell, B cell, …) using marker genes or reference atlases (Azimuth, CoDi).
[Normal] Differential expression (DE): Which genes are up/down in exposed vs control, within one cell type. Wilcoxon rank-sum test; adjusted p-value (FDR) controls false discoveries.
[Normal] Pathway enrichment: Are DE genes over-represented in GO, KEGG, or Reactome pathways? Links gene lists to biology (e.g. interferon response, inflammation).
[Normal] Size-specific effects: Comparing DE gene sets: unique to 40 nm, unique to 200 nm, shared, or only in mixture.

[Heading 2] 8.2 Glossary (quick reference)

[Normal] CoDi – Reference-based cell type labels provided with the dataset.
[Normal] DE – Differential expression – statistical comparison between groups.
[Normal] FDR / padj – False discovery rate – corrected p-value for multiple testing.
[Normal] HVG – Highly variable genes.
[Normal] logFC – Log2 fold change between two groups.
[Normal] PBMC – Peripheral blood mononuclear cells.
[Normal] PSNP – Polystyrene nanoparticle.

[Normal] Scanpy – Python library for scRNA-seq analysis.
